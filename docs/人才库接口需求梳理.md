## 2. 客户提供的 JSON 当前情况

### 2.1 文件结构

`人才库.json` 当前是一个 Elasticsearch 风格的检索结果样本，不是前端可直接消费的业务接口响应。

顶层结构大致为：

```json
{
  "took": 154,
  "timed_out": false,
  "_shards": {},
  "hits": {
    "total": {
      "value": 10000,
      "relation": "gte"
    },
    "hits": [
      {
        "_id": "L29598513",
        "_source": {
          "ID": "L29598513",
          "CNAME": "朱秋萍",
          "AORG": "南昌大学",
          "PROVINCE": "江西",
          "CITY": "南昌",
          "ORGTYPE": ["YY"]
        }
      }
    ]
  }
}
```

### 2.2 关键判断

1. 这份数据更像“搜索结果样本”，不是正式 API 契约。
2. `hits.total.relation = "gte"`，意味着总数可能只是“>=10000”，不是精确总数。
3. 样本内可见 10 条命中记录，很多字段名存在，但大部分值为空。
4. 它能支撑一部分“人才搜索/基础列表/基础详情”，但不能直接覆盖当前项目里的全部人才能力。

### 2.3 样本里字段情况

样本 `_source` 共出现约 93 个字段，比较稳定的字段如下：

| 字段 | 样本非空率 | 用途判断 |
| --- | --- | --- |
| `ID` | 10/10 | 人才唯一标识 |
| `CNAME` | 10/10 | 姓名 |
| `AORG` | 10/10 | 所属机构 |
| `PROVINCE` | 9/10 | 人才所在省份 |
| `CITY` | 8/10 | 人才所在城市 |
| `ORGTYPE` | 8/10 | 机构类型 |
| `TAGLARG` | 10/10 | 扩展标签，可用于分类或领域补充 |
| `BORG` | 4/10 | 二级机构/院系，可用于详情页 |

样本里字段名存在，但值基本为空或极不稳定的字段如下：

| 字段 | 样本非空率 | 影响 |
| --- | --- | --- |
| `TITLE` | 0/10 | 当前多个页面要展示职称 |
| `H` | 0/10 | 当前页面大量使用 H 指数 |
| `DIRECTION` | 0/10 | 当前人才页和详情页都需要研究方向 |
| `INTRO` | 0/10 | 详情简介不足 |
| `ABSTRACT` | 0/10 | 详情简介不足 |
| `KEYWORD` | 0/10 | 研究方向分布/关键词分析无法直接做 |
| `CATE` | 0/10 | 学科领域不足 |
| `EDU` | 0/10 | 学历信息不足 |
| `DEGREE` | 0/10 | 学位信息不足 |
| `GENDER` | 0/10 | 基本信息不足 |
| `PHOTOPATH` | 0/10 | 头像不足 |
| `TEL` | 0/10 | 联系方式不足 |
| `EMAIL` | 0/10 | 联系方式不足 |
| `TAGS` | 0/10 | 标签不足 |
| `journalCount` | 0/10 | 论文数不足 |
| `quoteCount` | 0/10 | 引用数不足 |
| `INDUSTRY` | 1/10 | 产业归属不稳定 |

### 2.4 当前 JSON 可直接利用的字段

适合直接用于“人才搜索/基础卡片/基础筛选”的字段：

- `ID`
- `CNAME`
- `AORG`
- `PROVINCE`
- `CITY`
- `ORGTYPE`
- `TAGLARG`
- `BORG`
- `ORGID`
- `ORGPROVINCE`
- `ORGCITY`
- `NATIVEPROVINCE`
- `NATIVECITY`

### 2.5 当前 JSON 的核心不足

当前样本无法证明它能稳定提供下列能力：

- 人才职称
- H 指数
- 论文数、专利数、成果数
- 研究方向
- 学科领域
- 头像
- 联系方式
- 合作人才关系
- 合作机构关系
- 年度趋势
- 论文列表
- 专利列表
- 宜昌人才库里的 HR/技能人才字段

## 5.1 人才搜索接口

### 对应页面

- [TalentGraph.tsx](C:/work/yichang/yc-new/yc/src/pages/Talent/TalentGraph.tsx)
- [Industry/index.tsx](C:/work/yichang/yc-new/yc/src/pages/Industry/index.tsx)
- [IndustryTree/index.tsx](C:/work/yichang/yc-new/yc/src/components/IndustryTree/index.tsx)
- [industryChainAggregation.ts](C:/work/yichang/yc-new/yc/src/services/industryChainAggregation.ts)
- [ScreenIndustry/index.tsx](C:/work/yichang/yc-new/yc/src/pages/Screen/ScreenIndustry/index.tsx)

### 为什么需要

用于：

1. 顶部关键词搜索人才。
2. 节点下钻看相关人才。
3. 产业链整链汇总人才。
4. 大屏中按产业关键词查宜昌人才。

### 当前代码中的请求参数

当前 `searchExperts` 使用：

- `key`
- `from`
- `size`
- `city`

建议客户接口至少支持：

- `keyword`
- `page` 或 `from`
- `pageSize` 或 `size`
- `province`
- `city`
- `orgType`
- `industry`
- `sort`

### 页面实际需要的响应字段

| 字段 | 用途 | JSON 样本是否有 |
| --- | --- | --- |
| `ID` | 人才唯一标识、跳详情、去重 | 有 |
| `CNAME` | 姓名 | 有 |
| `AORG` | 所属机构 | 有 |
| `TITLE` | 职称、列表展示 | 字段有，但样本无值 |
| `H` | H 指数、排序、标签 | 字段有，但样本无值 |
| `QIKAN` | 论文数 | JSON 无该字段样本值 |
| `ZHUANLI` | 专利数 | JSON 无该字段样本值 |
| `CHENGGUO` | 成果数 | JSON 无该字段样本值 |
| `CHANXUEYANHZ` | 合作次数，产业页抽屉展示 | JSON 无 |
| `DIRECTION` | 研究方向 | 字段有，但样本无值 |
| `CATE` | 学科领域 | 字段有，但样本无值 |
| `PROVINCE` | 区域筛选 | 有 |
| `CITY` | 区域筛选 | 有 |
| `ORGTYPE` | 机构类型 | 有 |
| `TAGLARG` | 人才类型/学科标签补充 | 有 |
| `PHOTOPATH` | 头像 | 字段有，但样本无值 |
| `total` | 总数展示、分页 | 样本只有 ES total，不是正式接口字段 |

### 结论

客户当前 JSON 能支撑一部分基础搜索结果，但要支撑现有页面，仍需补：

- 精确 `total`
- `TITLE`
- `H`
- `QIKAN`
- `ZHUANLI`
- `CHENGGUO`
- `DIRECTION`
- `CATE`
- `CHANXUEYANHZ`

## 5.11 宜昌人才库接口

### 对应页面

- [YichangTalents.tsx](C:/work/yichang/yc-new/yc/src/pages/Talent/YichangTalents.tsx)

### 为什么需要

这个页面展示的是“宜昌本地人才名册”，不是纯学术专家搜索页。

### 当前页面需要字段

| 字段 | 用途 | JSON 样本是否有 |
| --- | --- | --- |
| `id` | 主键 | 可映射 `ID` |
| `name` | 姓名 | 可映射 `CNAME` |
| `gender` | 性别 | 字段有，但样本无值 |
| `education` | 学历 | 字段有，但样本无值 |
| `school` | 学校 | 无稳定字段 |
| `major` | 专业 | 无稳定字段 |
| `skillName` | 技能名称 | 无 |
| `certificate` | 证书 | 无 |
| `workingYears` | 工作年限 | 无 |
| `organization` | 单位 | 可映射 `AORG` |
| `position` | 岗位 | 无稳定字段 |
| `nativePlace` | 籍贯 | 可由 `NATIVE*` 部分映射 |
| `level` | 人才级别 | 无稳定字段 |
| `industry` | 行业 | 字段存在但极不稳定 |

### 结论

当前 `人才库.json` 不足以直接支撑这个页面。  
如果客户坚持“全部人才相关都用这份数据”，建议二选一：

1. 客户补一份面向本地人才库的人才名册接口。
2. 这个页面改版，不再使用当前这套 HR/技能人才字段。

## 5.12 岗位供需接口

### 为什么需要

这个页面展示的是岗位供需，不是人才个人数据。

- `occupationName`
- `headcount`
- `workRegion`
- `educationMin`
- `salaryMin`

这个页面不应该由 `人才库.json` 承担。

## 8. 最终结论

### 8.1 客户当前 JSON 能做什么

可以支撑：

- 基础人才搜索
- 基础人才列表
- 基础地区筛选
- 基础机构筛选
- 基础标签展示

### 8.2 客户当前 JSON 还不能可靠支撑什么

不能可靠支撑：

- H 指数和成果统计
- 职称和研究方向
- 关系图
- 合作人才/合作机构
- 年度趋势
- 论文列表
- 专利列表
- 宜昌人才库现有页面
- 岗位供需页

### 8.3 给客户的建议

建议客户不要把这份 JSON 当成最终接口，而是当成：

1. 字段来源样例
2. 搜索索引样例
3. 后台建接口的数据源之一

最终还是要提供前端友好的业务接口，至少要把：

- 精确总数
- 稳定字段
- 关系数据
- 聚合数据
- 明细列表

这几类能力补齐。
